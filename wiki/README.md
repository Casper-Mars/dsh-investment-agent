# dsh-finance Wiki

本目录是 dsh-finance 项目的**知识合成层**，不是代码的副本，也不是飞书文档的搬运站。

## 三层结构

| 层 | 位置 | 职责 |
|---|---|---|
| 证据层 | 代码、测试、`CHANGELOG.md`、飞书设计文档、git 历史 | 唯一事实来源 |
| 合成层 | `wiki/**/*.md` | 人可读的结论：是什么、为什么、怎么用 |
| 导航层 | `index.md`、`reports/lint.md` | 由脚本生成，不手工维护 |

## 页面类型

```
wiki/
├── entities/     实体：项目、插件、外部系统（一页一个）
├── concepts/     概念：某个子系统怎么运作（一页一主题）
├── decisions/    决策记录 ADR：为什么这样做，替代方案是什么
├── guides/       操作手册：安装、配置、排障、发布
├── sources/      证据索引：飞书文档、外部规范、关键代码入口
├── _templates/   新建页面的模板
├── index.md      自动生成
└── reports/      自动生成（lint）
```

## 写作规则

1. **路径即 ID**：页面身份由文件路径决定，不写 `id` 字段。
2. **不写 frontmatter**：日期、作者、版本一律由 git 承担；页面头部只允许一行 `>` 摘要。
3. **一页一主题**：标题即结论，正文先给结论再给细节。
4. **必须有 `## 来源`**：每条来源写成行内反引号包裹的仓库相对路径（如 `src/tools/index.ts`），或完整 URL。脚本会校验路径是否存在。
5. **用 wikilink 连接**：`[[concepts/architecture|架构总览]]`；不要复制粘贴其它页面的正文，链接过去。
6. **不抄代码**：只写入口文件、契约、关键约束；实现细节以代码为准，改动代码时同步改页面结论。
7. **代码可推导的事实不手写**：工具数量、skill 清单这类内容，优先在页面里指向代码入口，必要时再列快照。

## 维护命令

```sh
pnpm wiki         # 重建 index.md 与 reports/lint.md
pnpm wiki:check   # 只检查：断链 / 缺来源 / 缺标题 / 孤儿页，非零退出即失败
```

标记块 `<!-- wiki:index:start -->` 与 `<!-- wiki:index:end -->` 之间由脚本接管，块外可以写人工备注。

## 什么时候更新

- 改动 `src/` 的公开契约（工具入参出参、skill 注册方式、任务结局语义、目录布局）→ 同步对应 concept 页。
- 做了一个**以后可能被重新讨论**的技术选择 → 新增一条 `decisions/NNNN-*.md`，不要只写在 commit message 里。
- 新增外部依赖或飞书设计文档 → 登记到 `sources/index.md`。
- 每次提交前跑 `pnpm wiki:check`（建议后续接入 CI）。
